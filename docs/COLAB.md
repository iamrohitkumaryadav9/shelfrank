# Running the notebooks on Google Colab

ESCI is processed only here. Each notebook is one self-contained file with every path in its first code
cell, so it also runs on Kaggle or any Linux machine.

## Seed-query notebook (Phase 2, CPU)

`notebooks/esci_seed_queries.ipynb`, generated by `scripts/build_seed_notebook.py` from tested modules.

1. Open https://colab.research.google.com and sign in.
2. **File > Upload notebook**, then choose `notebooks/esci_seed_queries.ipynb` from the local repository.
   Uploading is the simplest way while the repository is private, because Colab needs no GitHub access.
3. **Runtime > Change runtime type**: Python 3, hardware accelerator **CPU**.
4. **Runtime > Run all**. No Drive mount, login or key is needed.
5. Allow multiple downloads if the browser asks. The last cell downloads three files. If it does not, open
   the folder icon on the left, then `shelfrank_seed/out`, and download each file.
6. Move them, with their names unchanged, into `data/esci/`:
   `esci_seed_queries.txt`, `esci_prompt_dev.txt`, `esci_seed_manifest.json`.
7. In PowerShell, from the repository root:

```powershell
.venv\Scripts\python.exe scripts\check_seed.py
```

Every line must say `ok`. The check covers hashes, counts, overlap and WANDS leakage.

| | |
| --- | --- |
| Download | 1.16 GB into the Colab machine, verified by SHA-256 |
| Memory | Product titles are streamed in batches of 20,000 rows. The manifest records the measured peak |
| Disconnect | Nothing is saved between sessions. Run all again: sampling is seeded, so the result is the same |

## Fine-tuning notebook (Phase 3, GPU)

`notebooks/finetune_bge_esci.ipynb`, generated by `scripts/build_finetune_notebook.py` from tested modules.
It needs a Google account with about 2 GB free in Drive. No key or Hugging Face login.

1. Open https://colab.research.google.com and sign in.
2. **File > Upload notebook**, then choose `notebooks/finetune_bge_esci.ipynb`.
3. **Runtime > Change runtime type**: Python 3, hardware accelerator **T4 GPU**, then Save.
4. **Runtime > Run all**. Allow access to Google Drive when asked. The notebook writes only to the folder
   `MyDrive/shelfrank_ft`.
5. Leave the tab open. Training prints its step, loss and the minutes left.
6. If the session disconnects, or a cell says "time limit reached", choose **Runtime > Run all** again.
   Finished stages are skipped and training continues from its last checkpoint. Nothing is lost beyond the
   last 500 steps.
7. The last cell downloads `bge_small_esci.zip`. If it does not, download it from `MyDrive/shelfrank_ft`.
8. In PowerShell, from the repository root (about 35 minutes of CPU, resumable):

```powershell
Expand-Archive "$HOME\Downloads\bge_small_esci.zip" artifacts\models
.venv\Scripts\python.exe scripts\encode_products.py bge_small_esci
```

9. Keep `MyDrive/shelfrank_ft` until the Phase 3 results are committed, then delete it.

| | |
| --- | --- |
| Data | ESCI US small version, training split. Queries that resemble a WANDS query are removed, and 500 ESCI queries are held out |
| Time | One session stops itself after 100 minutes of training and can be continued. Wall time per session, every resume and every step's loss go to `MyDrive/shelfrank_ft/run_log.json`, and into `training.json` |
| Check on another machine | `reference_embeddings.json` holds the vectors of 20 invented texts |
| Checkpoints | Every 500 steps, two alternating files, so a crash while saving keeps the previous one |
| Same result after a break | A test shows that interrupted and uninterrupted training give identical weights on CPU |
| If the int8 export fails | The weights are packaged anyway, and the error is recorded in `training.json` |
| Other platforms | On Kaggle it uses `/kaggle/working`. Elsewhere it uses the current folder |
